# Firedoor v0.8 — Slice 8C2: consent-gated detached proof pair reader

**Expected parent:** `fce85ec` (`feat/v08-proofs`). This slice is offline and read-only; it adds **no CLI command**, API endpoint, source collector, Terraform/Kubernetes operation, comparison export, or output file.

## Why this boundary exists

8C1 compares two separately supplied, structurally valid Boundary Proof documents in memory. It does **not** obtain those documents. The 8B2 exporter produces only one historical detached report from the reviewed v0.5 source, and that report does **not** establish a genuine baseline/hardened experiment. This 8C2 reader must not use that single report twice or guess a missing profile.

## The fixed, private input contract

`prooflens.LoadApprovedBoundaryProofPair(root, consent)` requires the exact approval string `I-APPROVE-FIREDOOR-V08-OFFLINE-PROOF-PAIR-READ` and reads only these fixed Git-ignored paths:

- `docs/evidence/local/v08-baseline-boundary-proof.json`
- `docs/evidence/local/v08-hardened-boundary-proof.json`

**Neither file is provided or generated by this slice.** Before any future real review, both must be deliberately supplied as separately reviewed v0.8 Boundary Proofs. Never copy a single historical report to both inputs or alter its profile to imitate a second experiment. These paths are never committed.

The loader requires the actual Firedoor checkout root, an approved branch, ignored and untracked inputs, ordinary regular files in a non-symlinked local evidence directory, two distinct filesystem identities, and bounded canonical v0.8 JSON with no extra fields or trailing data. It independently validates each report and passes the pair to `reporting.CompareBoundaryProofs` to enforce baseline/hardened profiles, different IDs, matching scenario and route, and unmodified INCONCLUSIVE limitations. Invalid inputs are rejected without writing anything.

File identity and JSON checks establish **local structural consistency only**. They cannot establish that either input was collected independently, that its artifact hashes are authentic, or that a before/after experiment actually occurred. A qualified reviewer must separately verify provenance and experiment conditions. Both the verdict and drift assessment remain `inconclusive` / `not_assessed`.

## Tests and release sequencing

The Go tests use synthetic fixtures in disposable Git repositories and verify a successful read-only comparison, absent consent, missing inputs, swapped profiles, duplicate proof IDs, mismatched scope, forged verdicts/limitations, unknown fields, malformed/oversized JSON, symlinks, hardlinks, tracked files, and invalid checkout roots. Tests do not open your private project reports.

From the Firedoor repository in Windows PowerShell 5.1:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\v08\Test-FiredoorV08Slice8C2.ps1
```

After review and CI, the next slice **8C3** may add a separate explicit-consent CLI read/compare/export operation. That must retain fixed local destinations, refuse overwrite and ensure private files stay ignored. 8D/8E will handle additional hardening, user-facing review experience, documentation and PR quality gates.
